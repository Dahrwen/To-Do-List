SECTION 1: EXECUTIVE ARCHITECTURAL OVERVIEW
================================================================================
This application is a modern Single Page Application (SPA) built with React 18,
Vite 6, and the official Supabase JavaScript SDK (`@supabase/supabase-js`).
It serves as a centralized, privacy-first personal and academic productivity
repository featuring:
  1. Dual Authentication: Email/Password + Google OAuth 2.0 ("Continue with Google").
  2. Read-Only Google Classroom Activity Sync: Imports active courses and
     published assignments, auto-archives completed (`TURNED_IN` / `RETURNED`)
     submissions, excludes archived/hidden classes, and displays the official
     Google Classroom badge on imported task cards.
  3. Full Date & Time (`timestamptz`) Deadlines: Supports exact date and time
     deadlines (e.g., `Nov 06 2026 • 11:59 PM`) across Google Classroom imports,
     manual task creation/editing, and calendar views.
  4. Nearest-Deadline-First Priority Sorting: Automatically orders active and
     archived tasks chronologically so the most urgent upcoming deadlines appear
     first, with `"No due date"` tasks placed at the bottom.
  5. Interactive Calendars: A 14-day horizontal draggable `MiniCalendar`
     carousel and a full-month 7-column `BigCalendar` grid matched in the user's
     local timezone.

SECTION 2: GOOGLE OAUTH 2.0 FLOW (END-TO-END HANDSHAKE & TOKEN LIFECYCLE)
================================================================================

2.1 Key OAuth 2.0 Concepts & Terminology
--------------------------------------------------------------------------------
  * `client_id` (Public Identifier):
    A unique identifier generated in Google Cloud Console (`APIs & Services ->
    Credentials -> OAuth 2.0 Client IDs`) that identifies your application to
    Google's login servers.
  * `client_secret` (Confidential Backend Secret):
    A private cryptographic secret paired with your `client_id`. It is stored
    ONLY inside your Supabase Dashboard (`Authentication -> Providers -> Google`)
    and NEVER placed in frontend React code or committed to GitHub.
  * `Redirect URI` (Callback URL):
    The exact URL where Google is allowed to send the user after they approve
    the consent screen:
      1. Google -> Supabase Auth Callback:
         `https://<your-project-ref>.supabase.co/auth/v1/callback`
      2. Supabase Auth -> Your Frontend App (`redirectTo`):
         `window.location.origin` (e.g., `http://localhost:5173`)
  * `Authorization Code`:
    A single-use temporary code Google sends to Supabase's `/auth/v1/callback`
    endpoint after the user clicks "Continue" on the Google consent screen.
    Supabase exchanges this code + `client_secret` on the backend for tokens.
  * `access_token` (Supabase JWT) vs. `provider_token` (Google OAuth Token):
    - `session.access_token`: A JSON Web Token (JWT) issued by Supabase that
      authenticates the user with your Supabase PostgreSQL database.
    - `session.provider_token`: The Google OAuth 2.0 Bearer token issued by
      Google that authorizes read-only `GET` requests to
      `https://classroom.googleapis.com/v1/*`.
  * `refresh_token`:
    A long-lived token issued by Google when `access_type: 'offline'` and
    `prompt: 'consent'` are requested. Used by backend services (such as
    `supabase/functions/sync-classroom/index.ts`) to request a new Google
    `access_token` after the 1-hour expiry without prompting the user again.

2.2 Incremental Authorization (Why We Request Scopes in Two Stages)
--------------------------------------------------------------------------------
  1. Stage 1 — Basic Sign-In (`AuthModal.jsx` -> `handleGoogleAuth`):
     Calls `supabase.auth.signInWithOAuth({ provider: 'google' })` with only
     basic profile/email identity scopes. Users can log in immediately without
     seeing extra permission prompts.
  2. Stage 2 — Incremental Classroom Consent (`App.jsx` -> `handleConnectClassroom`):
     Only when the user clicks **"Connect to Google Classroom"** in the top-right
     profile dropdown does the app request the Google Classroom read-only scopes:
     ```javascript
     await supabase.auth.signInWithOAuth({
       provider: 'google',
       options: {
         redirectTo: window.location.origin,
         scopes:
           'https://www.googleapis.com/auth/classroom.courses.readonly ' +
           'https://www.googleapis.com/auth/classroom.coursework.me ' +
           'https://www.googleapis.com/auth/classroom.coursework.me.readonly',
         queryParams: {
           access_type: 'offline',
           prompt: 'consent',
         },
       },
     });
     ```

2.3 How `provider_token` is Captured & Persisted (`src/config/supabase.js`)
--------------------------------------------------------------------------------
When Supabase redirects the browser back to `http://localhost:5173`, it appends
the tokens to the URL hash fragment:
  `http://localhost:5173/#access_token=...&provider_token=ya29.a0...&token_type=bearer`

CRITICAL TECHNICAL DETAIL:
When `createClient(SUPABASE_URL, SUPABASE_KEY)` runs, Supabase's internal
`GoTrueClient` immediately parses and clears `window.location.hash` before React
components finish mounting. To guarantee `provider_token` is never lost,
`src/config/supabase.js` implements a 4-layer token capture & recovery strategy:
  * Layer 1 (Pre-Init Hash Intercept — Lines 5-16 of `src/config/supabase.js`):
    Reads `new URLSearchParams(window.location.hash.substring(1)).get('provider_token')`
    at module load time BEFORE `createClient()` executes, saving it to
    `sessionStorage` and `localStorage` under `'google_provider_token'`.
  * Layer 2 (Module-Level `onAuthStateChange` — Lines 28-39 of `src/config/supabase.js`):
    Captures `session.provider_token` the instant `INITIAL_SESSION` or `SIGNED_IN`
    fires, and wipes it immediately on `SIGNED_OUT`.
  * Layer 3 (`getGoogleProviderToken` Helper — Lines 48-84 of `src/config/supabase.js`):
    Checks (a) passed `session.provider_token`, (b) `sessionStorage`,
    (c) `localStorage`, and (d) Supabase's internal `sb-<project-ref>-auth-token`
    JSON in `localStorage`.
  * Layer 4 (Automatic 1-Hour Expired Token Detection & Seamless Re-Auth):
    Google OAuth `access_token`s (`provider_token`) have a strict 1-hour (`3600s`)
    lifetime. When a user returns to the app after >1 hour:
      1. `fetchClassroomEndpoint` (`src/services/classroomSync.js`) detects
         `response.status === 401`, immediately purges the expired
         `google_provider_token` from `sessionStorage` and `localStorage`, and
         throws a tagged `401` error.
      2. `handleLoginSuccess` and `runBackgroundClassroomSync` (`src/App.jsx`)
         catch the `401` (or missing token when `classroom_connected === 'true'`)
         and automatically invoke `supabase.auth.signInWithOAuth` (without
         `prompt: 'consent'`, guarded by `sessionStorage` key
         `classroom_auto_reauth_done` to prevent redirect loops). Because the
         user already approved the app, Google silently issues a fresh 1-hour
         `provider_token` and redirects back into the app to complete the sync.

SECTION 3: GOOGLE CLASSROOM API INTEGRATION (ENDPOINTS, SCOPES & MAPPING)
================================================================================

3.1 Required Google Cloud Console Setup & OAuth Scopes
--------------------------------------------------------------------------------
  1. API Enabled: **Google Classroom API** enabled in Google Cloud Console
     (`APIs & Services -> Library -> Google Classroom API`).
  2. OAuth Consent Screen Mode: While in **Testing** mode (free, no Google review
     required), your Google email must be listed under `Google Auth Platform ->
     Audience -> Test users`.
  3. Scopes Requested:
     - `https://www.googleapis.com/auth/classroom.courses.readonly`
       Allows listing the user's enrolled courses (`GET /v1/courses`).
     - `https://www.googleapis.com/auth/classroom.coursework.me.readonly` &
       `https://www.googleapis.com/auth/classroom.coursework.me`
       Allows reading coursework assigned to the user and their submission status.
     *Note on Central Repository Safety*: Even if Google's consent screen bundles
     `coursework.me` description text, our application code (`src/services/classroomSync.js`)
     executes **strictly `GET` requests** and contains zero `POST`, `PATCH`,
     `PUT`, or `DELETE` calls to Google Classroom.

3.2 Exact Google Classroom REST API Endpoints Called (`src/services/classroomSync.js`)
--------------------------------------------------------------------------------
Every request sends the header:
  `Authorization: Bearer ${providerToken}`
  `Accept: application/json`

  1. Fetch Active Enrolled Courses (`fetchCourses` — Lines 75-97):
     `GET https://classroom.googleapis.com/v1/courses?studentId=me&courseStates=ACTIVE&pageSize=100`
     (with fallback to `teacherId=me&courseStates=ACTIVE`).
     - Why `courseStates=ACTIVE`?
       Automatically excludes `ARCHIVED`, `PROVISIONED`, `DECLINED`, and
       `SUSPENDED` classes in Google Classroom so old/archived semesters never
       clutter your tracker.

  2. Fetch Published Coursework for Each Active Course (Line 364):
     `GET https://classroom.googleapis.com/v1/courses/${course.id}/courseWork?courseWorkStates=PUBLISHED&pageSize=100`
     - Retrieves `id`, `title`, `description`, `state`, `assigneeMode`,
       `dueDate` (`{ year, month, day }`), `dueTime` (`{ hours, minutes, seconds }`),
       and `alternateLink`.

  3. 3-Tier Student Submission Lookup & Automatic Completion (`Lines 340-445`):
     To reliably detect whether an assignment has been turned in across all
     Google Workspace / Classroom permission configurations, `classroomSync.js`
     uses a **3-tier submission lookup**:
       * Tier 1 (Course-Wide Wildcard with `userId=me`):
         `GET https://classroom.googleapis.com/v1/courses/${course.id}/courseWork/-/studentSubmissions?userId=me&pageSize=100`
       * Tier 2 (Course-Wide Wildcard without `userId=me`):
         `GET https://classroom.googleapis.com/v1/courses/${course.id}/courseWork/-/studentSubmissions?pageSize=100`
       * Tier 3 (Per-Assignment Fallback):
         If the course-wide `courseWork/-` wildcard returns 0 submissions (which
         occurs on some student accounts due to Google Classroom wildcard
         permission quirks), it queries each assignment directly:
         `GET https://classroom.googleapis.com/v1/courses/${course.id}/courseWork/${cw.id}/studentSubmissions?pageSize=20`

     Each submission record is evaluated by `processSubmissionRecord(sub)`:
       - Inspects `sub.state === 'TURNED_IN'`, `sub.state === 'RETURNED'`, and
         `sub.assignedGrade != null`.
       - Also inspects `sub.submissionHistory` (`stateHistory.state`) for
         `'TURNED_IN'` or `'RETURNED'`, only treating it as unsubmitted if the
         latest state is `'RECLAIMED_BY_STUDENT'` or `'CREATED'`.
       - Automatic Finish & Archive on Turn-In:
         * New tasks that are already turned in are inserted with `finished: true`.
         * Existing unfinished tasks (`finished: false`) in Supabase `Tasks`
           whose Classroom submission is now `TURNED_IN` or `RETURNED` are
           automatically updated to `finished: true` in Supabase (`tasksToUpdate`),
           moving them out of the active To-Do List and Mini/Big Calendars and
           into the **Archive** view.
       - Background Auto-Sync (`runBackgroundClassroomSync` in `src/App.jsx`):
         Runs automatically whenever the user switches back to the browser tab
         (`visibilitychange` / `window.focus`) and every 2 minutes while the
         tab is open, so turning in an assignment in Google Classroom
         automatically finishes the task in the tracker without manual clicks.

3.3 Hidden Classes Filtering & Database Cleanup
--------------------------------------------------------------------------------
In addition to excluding `ARCHIVED` classes from Google Classroom automatically:
  1. `localStorage.getItem('hidden_classroom_courses')` stores any active classes
     the user manually unchecked in the **"Filter Classes"** modal (`Header.jsx` ->
     `onManageCourses` -> `App.jsx`).
  2. During `syncGoogleClassroomTasks` (Lines 232-270) and when toggling a class
     off in `handleToggleCourseVisibility` (`App.jsx`), any previously imported
     tasks in Supabase `Tasks` belonging to an archived or hidden course are
     automatically deleted from Supabase and filtered out of `displayedTasks`
     and `allUnfinishedTasks`.

3.4 UTC `dueDate` + `dueTime` to ISO `timestamptz` Conversion (Lines 458-482)
--------------------------------------------------------------------------------
Google Classroom's REST API returns `dueDate` and `dueTime` in **UTC** (Coordinated
Universal Time). For example, an assignment due on **Nov 6, 2026 at 11:59 PM**
in `UTC+8` (Philippines/Singapore/Taipei time) is returned by Google as:
  `dueDate: { year: 2026, month: 11, day: 6 }`, `dueTime: { hours: 15, minutes: 59 }`

To store and display the exact deadline with time in Supabase's `timestamptz` column:
  ```javascript
  const hours = cw.dueTime.hours ?? 0;
  const minutes = cw.dueTime.minutes ?? 0;
  const seconds = cw.dueTime.seconds ?? 0;
  deadlineIso = new Date(
    Date.UTC(year, month - 1, day, hours, minutes, seconds)
  ).toISOString();
  ```
  - If an assignment has a `dueDate` but no `dueTime`, it defaults to `11:59 PM`
    local time: `new Date(year, month - 1, day, 23, 59, 0).toISOString()`.
  - If an assignment has no `dueDate` at all, `Deadline` is stored as `null`
    and displayed as `"No due date"`.
  - When `App.jsx` (`formatTask`) or `TaskDetailsModal.jsx` reads `task.Deadline`,
    `new Date(task.Deadline)` converts the ISO UTC timestamp back into the user's
    local timezone and formats it as:
    `"Nov 06 2026 • 11:59 PM"`

3.5 Task Mapping Schema, Multi-Row Indexing & Deduplication
--------------------------------------------------------------------------------
Each Google Classroom assignment is mapped to a row in Supabase `Tasks`:
  - `userID`: Integer `userID` from `Accounts` table
  - `TaskName`: `cw.title`
  - `Description`:
    Line 1: `[Google Classroom] <Course Name>`
    Body:   `<cw.description>`
    Footer: `Classroom Link: <cw.alternateLink>`
  - `Deadline`: ISO-8601 `timestamptz` string (or `null`)
  - `Type1..Type6`: `Type4: true` (`Academics`), all others `false`
  - `finished`: `true` if `TURNED_IN` / `RETURNED`, otherwise `false`
  - Multi-Row Lookup & Deduplication (`addToExistingMap` — Lines 301-337):
    Existing rows in Supabase are indexed in `existingTaskMap` (storing an
    **array of rows** per key so even duplicate rows are updated together) across
    three composite keys:
      1. `link::<alternateLink>`
      2. `title_course::<title>::[google classroom] <course>`
      3. `classroom_title::<title>` (fallback for legacy Classroom tasks)
    If a matching task already exists in Supabase, it is never duplicated;
    instead, if its `Deadline` changed or if `isCompleted && !matchedTask.finished`,
    `classroomSync.js` updates all matching rows in `tasksToUpdate`.

SECTION 4: ENVIRONMENT VARIABLES & SECURITY PROTOCOLS
================================================================================

4.1 Complete Environment Variable Reference (`.env.local` vs Server Secrets)
--------------------------------------------------------------------------------
1. Client-Safe Environment Variables (Stored in local `.env.local` ONLY):
   - `VITE_SUPABASE_URL=https://<your-project-ref>.supabase.co`
     Your Supabase project's REST and Auth endpoint URL.
   - `VITE_SUPABASE_KEY=eyJhbGciOiJIUzI1NiIs...`
     Your Supabase **anon (public)** key. This key is safe to use in the browser
     because it only grants access permitted by your database rules and cannot
     bypass security like a service role key.

2. Server-Only Secrets (Stored in Supabase Dashboard -> Auth / Edge Functions):
   - `GOOGLE_CLIENT_ID`: Stored in Supabase Auth -> Providers -> Google.
   - `GOOGLE_CLIENT_SECRET`: Stored strictly in Supabase Auth -> Providers ->
     Google (and Edge Function Secrets if using `sync-classroom`). **NEVER**
     placed in `.env.local` with a `VITE_` prefix and **NEVER** in frontend code.
   - `SUPABASE_SERVICE_ROLE_KEY`: Admin key that bypasses Row Level Security.
     Used exclusively inside Deno Edge Functions (`Deno.env.get("SUPABASE_SERVICE_ROLE_KEY")`),
     never on the client.

4.2 Multi-Layer Security & Privacy Protections Implemented in Code
--------------------------------------------------------------------------------
  1. `.gitignore` Enforcement:
     `.env`, `.env.local`, `node_modules`, `dist`, `.vite`, and `.build.txt` are
     listed in `.gitignore` so local environment files are never committed to Git.
  2. Zero Hardcoded Keys:
     `src/config/supabase.js` reads `import.meta.env.VITE_SUPABASE_URL` and
     `import.meta.env.VITE_SUPABASE_KEY`. No keys or secrets exist in source files.
  3. First-Name-Only Greeting (`formatCapitalizedFirstName` in `App.jsx` & `Header.jsx`):
     Parses `"LastName, FirstName"` or full names so only the single capitalized
     first name (e.g. `"Dharwin"`) is shown in the header—never exposing surnames
     or email addresses in the UI.
  4. Avatar Referrer Privacy (`Header.jsx` Line 168):
     Uses `referrerPolicy="no-referrer"` on the `<img>` tag so fetching the user's
     Google profile picture never leaks the application's URL to external servers.
  5. Strict Database User Isolation:
     Every Supabase query (`select`, `insert`, `update`, `delete`) on `Tasks`
     filters by `.eq('userID', userId)` so a user only ever accesses their own rows.

5.2 Step-by-Step Local Setup & Execution Commands
--------------------------------------------------------------------------------
  1. Install Dependencies:
     ```bash
     npm install
     ```
     Reads `package.json` and `package-lock.json` and installs all packages into `node_modules/`.

  2. Configure Local Environment (`.env.local`):
     Copy `.env.example` to `.env.local` and fill in your two client variables:

     ```bash

     ```
     Launches Vite with Hot Module Replacement (HMR). Open `http://localhost:5173`.

  4. Build for Production:
     ```bash
     npm run build
     ```
     Verifies all imports, bundles JSX/CSS, and outputs optimized static files to `dist/`.
